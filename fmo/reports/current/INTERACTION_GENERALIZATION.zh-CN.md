# 从蛋白–小分子扩展到PPI、蛋白–RNA与RNA–配体

核查日期：2026-10-21。本文是扩展设计与证据审查，**不是已经完成的新体系验证结果**。
文献题录、作者摘要和核查日期保存在 `INTERACTION_GENERALIZATION_SOURCES.json`。

## 1. 结论与现状

**FMO的分片与跨伙伴相互作用分析可以扩展；当前工具的整条制备和排序流程还不能直接宣称适用。**
必须分别回答：①结构和化学模型是否正确；②跨界面能量能否可靠计算；③该分数是否预测实验亲和力。
算通或找出热点，只证明前两层的一部分，不证明第三层。

| 类型 | 可以复用 | 必须新建或验证 | 本项目现有证据 |
|---|---|---|---|
| 蛋白–蛋白，PPI | 氨基酸审计、蛋白分片思想、跨组PIEDA汇总、任务编排 | 两个多片段伙伴、多链生物学组装、双侧界面制备与截断、突变/绝对亲和力分开评估 | 有输入审计与计分入口；没有端到端排序验证 |
| RNA–小分子 | 配体化学身份校验、部分小分子制备、跨组PIEDA、执行与报告框架 | 核苷酸连接/切分/电荷/端基、RNA力场、RNA补氢、Mg与水网络、修饰核苷 | 有限的标准RNA重原子输入审计；没有RNA制备/分片验证 |
| 蛋白–RNA | 蛋白部分及上述基础设施 | RNA全部能力、双侧多片段、强带电界面的溶液条件与构象验证 | 同上；没有端到端排序验证 |

现有 `partner-intake` 只核查指定PDB链的基本重原子、残基名、距离等，输出
`BOUND_GEOMETRY_AUDITED_NEEDS_QM_FRAGMENT_MAPPING`，且 `ranking_eligible=False`。
它不是完整化学审计：不证明RNA的磷酸二酯键、缺失原子、糖环立体化学或端基正确；
当前每个伙伴只选一条PDB链，不能代替多链/mmCIF的通用生物组装选择器。
RNA–配体的PDB/SDF匹配使用分元素坐标分配，也不能代替完整键图同构校验。

`interface` 已能汇总任意两个非空、不相交的片段集合：检查全部A×B片段对覆盖、重复行、
PIEDA各分量闭合、有限数值和GAMESS正常终止。它依赖用户已提供正确片段映射与可用QM日志，
并不生成新类型的制备结构或QM deck；正常终止也不能代替完整的数值收敛审计。
生产蛋白分片目前是FACIO-like氨基酸主链切分/HOP_C与ACE/NME端帽，不能把RNA改名成氨基酸接入。

## 2. 到底迁移哪个分数

对于同一个制备好的AB复合物，定义：

\[
E_{\mathrm{interface}}(A,B)=\sum_{i\in A}\sum_{j\in B}\mathrm{PIE}_{ij},
\qquad S_{\mathrm{favorable}}=-E_{\mathrm{interface}}.
\]

- 蛋白–配体：A为蛋白片段，B通常是一个配体片段。
- PPI：A、B分别是两侧蛋白伙伴的全部入选片段；两侧都通常有多个片段。
- 蛋白–RNA：A是蛋白片段集合，B是RNA片段集合。
- RNA–配体：A是RNA片段集合，B是配体片段集合。

这仍然是现有tPIE的**跨伙伴求和思想**，不是改成ES，也不是偷偷换成三态差值。
选中A–B不等于底层只存在A–B：单体自洽极化及环境会影响这些片段对的能量。
应明确区分A、B和环境E（水、离子、辅因子）；不能把A–环境、B–环境的能量悄悄并入A–B总分。
不同片段划分、环境、截断或QM方法所得数值也不保证相等。

三态 `E(AB)-E(A)-E(B)` 是另一候选估计量，需要三态一致的可用总能量，不能从选择性
PIEDA日志冒充恢复完整FMO总能量。本轮先验证tPIE；不把三态、PBSA、熵等一次性混入主分数。

**边界：**以上不是实验结合自由能。对PPI/RNA等新类型，溶剂、离子、构象变化和熵的遗漏是否
破坏排序需要实测，不能用蛋白–小分子结果推定。跨不同大小/净电荷的体系直接合并相关性，
可能只反映尺寸或电荷；这是假设性风险，必须诊断，而非本项目已证明的根因。

## 3. 为什么有可行性，又为什么不能直接搬参数

### 原始研究能证明什么

`FMO_RNA`（DOI 10.1016/j.jmgm.2020.107695）实际计算了RdRp–RNA–Remdesivir体系：
ABINIT-MP、FMO2-MP2/6-31G*，蛋白按氨基酸分片，RNA碱基与糖–磷酸骨架分开。
这是FMO处理蛋白/RNA混合体系的直接证据，但**不是当前GAMESS FMO2-DFTB3/PCM方案的验证**，
也不是RNA–配体亲和力排序benchmark。该文制备后去除水和离子的操作不能自动成为本工具的默认规则。

`DFTB3_P_S`（DOI 10.1021/ct401002w）提供P/S的DFTB3/3OB参数研究；
`DFTB3_MG_ZN`（DOI 10.1021/jp506557r）提供Mg/Zn参数与模型测试。
因此不能说“DFTB3完全没有P或Mg参数”。但存在元素参数不等于当前安装的参数对齐全，
更不等于带电磷酸–Mg–水位点在当前引擎、分片、PCM与力场组合中已经验证。
后者须做本地小模型对照，参数论文自身也明确存在能量精度与带电配体方面的限制。

### 不能原样推广的旧设置

| 旧流程设置 | 新类型的风险 | 扩展要求 |
|---|---|---|
| PDBFixer + PDB2PQR/PROPKA蛋白路径 | 蛋白可用的制备不代表RNA连接、电荷或修饰残基已被正确处理 | 按聚合物类型分派制备；蛋白工具只处理它支持的组分；混合体系重组后校验原子与键 |
| 当前固定受体、配体k10局部最小化 | PPI没有同样意义的“一个小配体”；RNA重排、配对与糖环可能受影响 | 新建各类型允许移动的原子与约束策略，保留现有路径作对照；不得直接承诺k10最优 |
| 5 Å全队列共享口袋 | 大界面两侧都可能被截断；带电RNA的远程环境可能重要 | 双侧界面区域+上下文；同队列固定规则；做口袋/环境收敛检查 |
| 冲突水与冲突氢规则 | RNA桥水与Mg水合壳可能有结构作用；金属近接不是普通碰撞 | 先判别配位/桥水/化学键，再修氢或修姿态；不能把关键水或离子直接删除 |
| 氨基酸HOP_C与ACE/NME | 核苷酸骨架、末端电荷和切键方式不同 | RNA专用片段模型、核对原子归属、总电荷、切键与端基 |
| 原有稳健软压缩 | 只能改变Pearson尺度，不修复错误结构；严格单调时不改变Spearman/Kendall | 报告原始与变换分数，冻结变换策略；不能沿用旧靶点中心/尺度冒充通用校准 |

## 4. 应固化的通用架构

保留已经验证的protein_ligand路径，新增按化学类型分派的adapter，而非复制三份互不一致的工具：

```text
PDB/mmCIF + 配体SDF + 明确的伙伴/环境声明
  → 原始组分清点：聚合物、修饰残基、金属、辅因子、水、共价连接
  → 统一复合物图：原子/残基/伙伴/坐标/键/链与结构身份
  → 类型adapter：protein、RNA、ligand、已注册的metal/cofactor
  → 图规则生成可解释的诊断与修复计划
  → 执行已验证修复；未知模型进入结构化的待支持报告
  → 分类型补氢/质子化/电荷检查与受约束制备
  → 双侧界面与环境选择、分片和QM参数完整性检查
  → FMO + 完整收敛审计 + A×B PIEDA覆盖检查
  → tPIE、分量/残基/核苷酸热点、覆盖率、耗时与可比性报告
```

图是可解释的诊断与调度结构，不是从亲和力标签训练的GNN或“看图自动变准确”。
必须保留原始→制备→MM→QM的原子映射，修复前后清点守恒；删除必须有明确、可审计的规则。
坐标接近只能生成候选接触边，不能直接认定共价键、配位键或氢键。

最小图信息包括：化学身份/形式电荷/聚合物连接；链与生物学组装；共价跨伙伴连接；
二硫键、修饰核苷和非标准残基；金属配位与候选桥水；RNA糖环、磷酸连接、末端与缺失原子；
有条件定义的氢键、盐桥与碱基配对/堆积；碰撞、接触距离及界面覆盖。
质子化状态、金属配位和实验条件存在歧义时应显式记录假设，不能由距离图唯一推断。

同一个错误编码应对应修复动作、适用边界、后验检查与回归样例。未支持化学不能因“至少要给分”
而静默删除；应给出可读的原因、缺失模型与下一步。易用性意味着可诊断、可恢复，不意味着伪造成功。

## 5. 基准如何选，不能混淆什么

| 任务 | 已核实的数据来源 | 正确使用方式与限制 |
|---|---|---|
| PPI绝对亲和力 | Affinity Benchmark v2，DOI 10.1016/j.jmb.2015.07.016；论文报告179条affinity entries，另有230条docking entries | 亲和力集与docking集分开；筛选结构、组装及测量条件，不能把230条全当亲和力标签 |
| PPI突变效应 | SKEMPI 2.0，DOI 10.1093/bioinformatics/bty635；论文报告7085条mutation binding data | 测ΔΔG而非同靶点小分子排序；野生型晶体结构不代表每个突变体都有晶体结构；不可检测结合是删失值 |
| 蛋白–RNA | ProNAB，DOI 10.1093/nar/gkab848 | 同时含DNA与RNA、野生型与突变，须单独筛RNA并关联匹配结构；论文的超过20000条记录不是20000个RNA晶体复合物 |
| RNA–配体结构 | HARIBOSS，DOI 10.1093/bioinformatics/btac483 | 含晶体/NMR/cryo-EM，须按实验结构类型筛选；结构库不能直接当完整亲和力benchmark |
| RNA–配体结构+候选亲和力 | HARIBOSS++，DOI 10.64898/2026.09.07.749797，2026-09-13预印本 | 作者摘要说明新增可用时的实验亲和力与MD；须核查每条配对、条件、许可和下载内容，不能假定全部有标签 |

推荐先形成“同一RNA靶点、相近条件、多配体且有实验复合物结构”的小系列，
以及“同一PPI复合物背景、结构变化可控”的突变系列；再做跨靶点外推。
具体合格条数、下载可用性、许可及去重后规模**尚未完成逐条筛选**，不能在此虚报。

对照必须区分实验晶体姿态、NMR模型、预测姿态和人工突变模型。
优先从实验复合物姿态测能量打分，避免把构象预测误差与打分误差混为一谈；
预测姿态端到端评测应另列一组实验，不能按标签挑最优姿态。

Boltz官方 `docs/prediction.md` 的affinity范围是**小分子–蛋白**，并警告RNA/DNA/cofactor
target输出不可靠。不能直接把Boltz2 affinity作为PPI、蛋白–RNA或RNA–配体的有效标准对照；
结构预测可用性也不等于affinity head适用。FEP同样要核查是否有适用于该任务的协议和匹配队列，
不能移用旧蛋白–小分子FEP指标。

## 6. 可执行阶段与验收

下表是后续任务设计，不表示已经启动这些QM或MD作业。

| 阶段 | 内容 | 验收与停止条件 |
|---|---|---|
| G0：数据与结构清单 | 三类数据分别筛结构–亲和力–条件，声明A/B/环境；建立多链/mmCIF映射 | 每条有来源、结构身份、伙伴选择和条件；缺失信息单列，不混入主评估 |
| G1：PPI技术先导 | 选1–3个结构较小、标准氨基酸、无未知化学的复合物；验证双侧分片与全A×B计分 | 原子/电荷/切键一致；正常终止且收敛；交换A/B计分一致；无缺对或重复对 |
| G2：RNA模型先导 | 核苷、二核苷酸/磷酸片段、小配体接触，随后Mg–磷酸–水模型 | 明确力场/QM参数对及端基；对小体系做更高层级参考；既查结构也查相对能量，不能只看是否收敛 |
| G3：三类端到端先导 | 在各类少量结构上接通图诊断→制备→FMO；记录自动修复与失败原因 | 无静默组分丢失；全部输入有结果或明确失败报告；整队列覆盖率和资源明细可复查 |
| G4：成组匹配消融 | 在完整合格队列上比较界面范围、制备约束、已验证水/离子策略；标签盲规则 | 每次只变一个处理或做预先声明的组合；对共同完成集配对比较，同时报告全队列覆盖率 |
| G5：冻结与迁移 | 冻结处理规则，在未参与方法选择的蛋白/RNA家族上验证 | 不用新标签调阈值/挑构象；Galectin3、原87、FXa、OpenBind及当前其余队列保持旧路径回归 |

**优先顺序：**先PPI技术先导，因为可复用氨基酸化学；并行规划RNA小模型，随后做RNA–配体，
最后接通蛋白–RNA。这个顺序是开发风险判断，不是承诺PPI的亲和力排序一定最容易。
RNA–配体更接近现有“同靶点多配体排序”的产品场景，但化学制备比PPI新增内容更多。

### 统一统计规则

- 以 `-tPIE` 对 `pKd` 等“越大越强”标签计算Pearson/Spearman/Kendall；突变任务另用
  `ΔtPIE = tPIE(mut)-tPIE(WT)` 对 `ΔΔG = RT ln(Kd_mut/Kd_WT)`，正值表示变弱。
- 不将Kd、Ki、IC50或不同温度/pH/盐/Mg条件未经说明地混成同一种标签。
- 每个靶点/复合物系列单列指标、样本数与覆盖率；跨体系汇总要说明权重。
- 做按复合物家族/系列分组的置信区间与外推切分，避免把近重复突变当成独立泛化证据。
- 诊断分数与界面面积、原子数、净电荷、磷酸数等的关系；只作混杂分析，不能未经验证就
  改成除以面积、按电荷校正或拟合新权重。保留无拟合tPIE为主对照。
- 软压缩只作为固定统计变换单列；Pearson变化不能冒充结构/物理模型改进。
- 分别报告制备、最小化、QM、重试的墙钟时间、CPU核时和GPU时间；不得沿用旧小分子单例成本。
- 没有数据前不承诺达到0.55或0.6；成功运行、修复覆盖率和排序提升是不同验收项。

## 7. 本轮完成与未完成

已完成：现有接口/分片能力核查；三类扩展的估计量与边界；原始文献和候选基准核实；
图驱动分派、化学模型验证、消融与冻结迁移的工程方案。

新的端到端执行器与全部跨类型QM/亲和力验证。因此目前没有这三类体系的新指标可汇报。
