# tPIE 单指标：结构、约束和多构象的全覆盖配对审计

日期：2026-10-15。本轮**仅比较原始 `tPIE`**，不将 PIEDA 的 ES/SOLV、三态或 PBSA 组合进分数。每个靶点先分别计算与实验亲和力的 Pearson/Spearman/Kendall，再按靶点例数加权；能量及实验 ΔG 同时取负号。所有 87 例及外部全部已完成配体均保留。运行：

```bash
../fmo87-pipeline-tool/envs/fmo87/bin/python scripts/audit_fmo_tpie_protocol_transfer.py
```

逐例、输入 SHA、各靶点相关与 1800 次靶点内配对 bootstrap 输出到 `runs/fmo87/ablation/tpie_protocol_transfer_20261014/{cases.csv,evaluation.json}`。脚本检验全 87 例配体身份及标签一致、dry19 对其他三个靶点的分数不变、三构象每例均值/中位数闭合且与历史汇总一致；外部对照要求完成状态和盲态结果 SHA 匹配。由于原 87 与外部集的这些方案均在看过标签之后研究，**统计区间只描述现有数据的配对差异，不能当作新目标的前瞻性能**。

**解释边界：**k10 和 k100 是约束强度不同的几何处理，87 例的成对差异支持保留 k10，但不保证未来靶点也更好。P38 去水改善点估计，k10 的配对区间仍跨零；去水应由预先规定的严重水冲突审计触发，并对整个靶点采用一个受体版本，**不能基于实验排序挑水**。Galectin3 的修复同时改变多项结构制备环节，不能单独归因于水或氢；FXa 在新处理后小幅下降，也不得掩去。三臂为完整的预注册聚合，但三臂简单均值既未提高原87 Pearson，也未显著改变 Kendall；没有将多构象升为默认生产项的依据。不同数据集的受体、初始结构和口袋不完全同源，不能把 0.601 直接当作外部运行保证。

**当前默认**：严格执行无标签结构/水冲突审计，同一靶点统一受体与口袋、所有配体统一 k10、输出同一计算协议的 `−tPIE` 排序；失败不出部分排序。仅当事先规定且完整覆盖时才启用多构象盲态平均，并与单构象配对报告；不要根据任何已知标签切换臂。这里没有提出新的 tPIE 后处理或保证改善 Pearson 的办法；下一项真实必要工作是冻结规则后对**未参与开发的全新系列**盲测。

## 重要更正：dry19 与新入口不是同一统一流水线

`python scripts/audit_fmo87_unified_water_provenance.py` 对原87例冻结输入逐靶点做了**不读取实验标签**的结构核查，完整输出 `runs/fmo87/ablation/tpie_unified_water_provenance_20261015.json`，包括源 PDB/SDF SHA、触发判断及每个水的残基 ID：

| 源靶点 | 例数 | 原始 PDB 晶水 | 新入口原始严重碰撞水 | 历史 dry19 分支去水 |
|---|---:|---:|---:|---:|
| CDK2 | 16 | 0 | 0 | 0 |
| JNK1 | 21 | 0 | 0 | 0 |
| P38 | 34 | 343 | **6** | **19** |
| TYK2 | 16 | 0 | 0 | 0 |

**为什么只处理 P38？**不是因为拿亲和力给 P38 单独调参，而是原87冻结 PDB 中其它三个靶点根本没有晶水；P38 的原始配体重原子到水氧最近距离约 `0.921 Å`，触发预定的 `<2 Å` 源水冲突判断。同一判断必须对每个新靶点运行。**为什么 6 与 19 不一样？**新 `geometry` 入口 `decide_fmo_structure_treatment.py` 只移除碰到任一配体且满足严重接触阈值的那几颗水（这里六颗），在 PDBFixer/PDB2PQR 和 k10 **之前**决定；旧 dry19 臂则在该源水冲突触发后，采用已制备受体/配体姿态的**全靶点共享口袋**选择冻结的 19 个水，经过旧的 PDB2PQR、固定受体 k10、共享口袋、GAMESS QM。原始未经 k10 的结构用全原子 5 Å 并集计算会得到 **20** 个水（比历史19多 HOH C693），再一次证明不能在源坐标中猜旧口袋 ID。历史原87没有逐例执行后来加入的 PDBFixer→清除其氢→PDB2PQR/PROPKA→重新审计的完整新入口，仅 CDK2/17 做过一次新入口端到端冒烟。

**部署边界**：现有 `0.6007/0.4392` 只能称为历史 `P38 dry19 + k10 + tPIE` 的 87 例结果；不能标记成新入口 `PDBFixer/PDB2PQR + 严重水冲突去水 + k10` 的成绩。已经固化的是“所有靶点同样运行无标签审计、每个靶点只用一个受体、全量成功才排序”的**决策原则**，但**同一可执行实现与 87 例新入口全量 QM 验证还没有完成**。若要重现 dry19 而不是一个新的去水实验，下一步必须在所有靶点经过同一个新制备+k10 后，按同一源水 `<2 Å` 触发规则取新受体的 5 Å 全靶点共享口袋去水、核对残基身份与同源姿态，然后完整重跑 87/87 QM；口袋残基集合或失败案例有变化应明确作为新协议报告，绝不能复用历史指标。

**2026-10-15 执行更新**：上段“新入口全量 QM 验证还没有完成”是重跑前的时间截面。现已按新入口**全87例重算 87/87**，P38 采用该入口的直接严重水规则（删 6 水），加权 tPIE **Pearson 0.6367、Spearman 0.6232、Kendall 0.4596**；完整输入/输出、四靶点表及旧 dry19 严格配对见 `docs/FMO87_NEW_FULL_PIPELINE_TPIE_20261015_CN.md`。两套不同协议均已分别明确命名，不能互相冒用指标。
